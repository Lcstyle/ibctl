API access

Scripts call this dashboard with a named API token, one per client, sent as Authorization: Bearer <token>. Every token has a type, chosen when it is created. A token is not a login: it can reach only the routes of its own type, while that type is enabled below, and nothing else. The dashboard password does not work as a Bearer token.

Using a token

Warm restart client. Warm restart takes the mode and nothing else. It answers 202 with the minute the restart is set for, or 429 with Retry-After while the minimum interval has not passed. Read how it went with GET, until warm is set. 

curl -X POST https://your-dashboard.example{{ root_path }}/api/v1/warm-restart \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"mode": "paper"}'

curl -H "Authorization: Bearer $TOKEN" \
  "https://your-dashboard.example{{ root_path }}/api/v1/warm-restart?mode=paper"

Gateway upgrade: CI. Reads the upgrade state and reports the image CI built. Gateway upgrade: maintenance. Reads the same state and reports what the swap did. A token cannot call the other type's report, and neither can save the upgrade policy. 

curl -H "Authorization: Bearer $TOKEN" \
  https://your-dashboard.example{{ root_path }}/api/v1/gateway/upgrade

curl -X POST https://your-dashboard.example{{ root_path }}/api/v1/gateway/upgrade/candidate \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"version": "10.51.1h", "sha": "<40-hex commit>", "status": "built"}'

curl -X POST https://your-dashboard.example{{ root_path }}/api/v1/gateway/upgrade/swap \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"version": "10.51.1h", "sha": "<40-hex commit>", "result": "ok"}'
